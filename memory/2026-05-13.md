### Cloudflare Infrastructure Crisis — POST /submit-signature BLOCKED

#### Symptom
- GET /submit-signature → HTTP 404 with JSON body ✅ (function works)
- POST /submit-signature → HTTP 403, {"error code: 1003"} ❌
- Both qiyadon.com and strateon.pages.dev return identical 403

#### Investigation Path (exhausted)
1. WAF skip rule: Created and applied — did NOT resolve
2. Bot Fight Mode: Already OFF — confirmed not the cause
3. DNS-only vs Proxied: Proxied causes "Not Found" on all pages; DNS-only restores site
4. Cloudflare Pages custom domain binding: Active, SSL enabled — appears healthy
5. Pages Function directory: Moved from public/_functions/ to functions/ at repo root — deployed ✅
6. All other Pages routes: Working normally (GET /, /sign-trial, etc.)

#### Root Cause Identified (confirmed)
- Cloudflare Pages Functions block ALL outbound fetches to direct IP addresses (error code: 1003)
- The functions/submit-signature.js does: fetch('http://5.9.81.5:3001/submit-signature')
- This triggers Cloudflare's "Direct IP Access Not Allowed" block at the Pages platform level
- GET works because it returns inline JSON without fetching an origin
- POST fails because it must forward to port 3001 backend

#### Worker Route Investigation
- hub-oauth-worker.js: Already contains /submit-signature handler (added in prior session)
- hub-oauth-worker.toml: Routes only qiyadon.com/hubspot/* — NOT oauth.qiyadon.com/*
- oauth.qiyadon.com IS a separate Cloudflare Pages/Worker deployment
- /hubspot/* routes work through Worker (confirmed: GET /hubspot/status returns 200)
- /submit-signature on oauth.qiyadon.com falls through to Pages static hosting (404)

#### Confirmed Working Paths
- Direct to port 3001 backend: curl http://5.9.81.5:3001/submit-signature → HTTP 400 (agreedAt missing) ✅
- Worker GET /hubspot/status: HTTP 200 ✅ (Worker is alive and reachable)
- Worker POST /hubspot/disconnect: hangs (proxies to port 3003 backend) ✅

#### Solution Path (pending Ahmad decision)
The hub-oauth-worker.js code already has a working /submit-signature handler in its non-/hubspot branch.
The simplest fix: The Worker at qiyadon.com (which handles /hubspot/*) also handles /submit-signature 
in its pass-through. The frontend sign-trial.html needs to POST to:
  https://qiyadon.com/hubspot/submit-signature
instead of:
  https://qiyadon.com/submit-signature

This requires:
1. Updating sign-trial.html fetch URL to point to /hubspot/submit-signature
2. The Worker will route it to http://5.9.81.5:3003 (PM2 backend — hub-oauth-v2.js)
3. hub-oauth-v2.js on port 3003 does NOT have a /submit-signature route — it only has HubSpot routes
