- Hallucination patterns: Alibaba Cloud, Qwen-based, container orchestration, etc.

#### Governance Layer
- RESTRICTED actions: hard stops, no override, even for Ahmad
- Approval-boundary reinforcement: classify → check → execute/log
- Ambiguity handling: LOW (proceed), MEDIUM (present to human), HIGH (MiniMax)
- Fallback escalation: confidence <0.7 → MiniMax

#### Telemetry Architecture
- Hallucination metrics: identity_drift, blocked_term, context_trunc (alert at >1%)
- Safety metrics: unsafe_output, restricted_hit, approval_denied (any RESTRICTED → alert)
- Routing metrics: latency, p95, fallback_freq, provider_uptime, retry_rate
- Confidence scoring: weighted sum of 5 factors (0-1 scale)
  - <0.5: reject → MiniMax
  - 0.5-0.69: re-validate with MiniMax
  - 0.7-0.89: use but flag
  - ≥0.9: high confidence

#### Production Safety Gates
| Gate | Requirement |
|---|---|
| Local-primary promotion | 0% hallucination 30 days, avg confidence ≥0.85, uptime >99.5% |
| Governance tasks | 0% hallucination 14 days, confidence ≥0.7 every request |
| Executive planning | Confidence ≥0.85 on all tasks 14 days, identity stable 30 days |

#### Recommendations
1. **Identity anchoring: MANDATORY before GPU deployment** — zero-cost, eliminates highest-risk failure mode
2. **Telemetry: MANDATORY before any promotion** — cannot measure quality without metrics
3. **Safest migration sequence:** Identity anchor (Week 1) → Telemetry (Week 1-2) → GPU deploy (Week 2) → Evaluation (Week 3) → Safety gate review (Week 4) → Production (Month 2+)
