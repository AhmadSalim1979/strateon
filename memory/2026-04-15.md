### Why live retry was NOT created (G-S2 block)
CRC gate G-S2 blocked the retry with `G-S2: not_T_class`.

**Root cause:** CRC's G-S2 reads error classification from `signal.dispatch.error_message` first, falling back to `task.error_message`. In the ADL signal-reader flow, when emitting `TASK_FAILED` signals for a failed task, the signal object does NOT transfer `task.error_message` into `dispatch.error_message`. The dispatch row itself also has `error_message = null`. So the classification sees no error message and returns `'U'` (unknown), not `'T2'`.

**This is a real ADL signal-reader gap**, not a CRC bug. The CRC gate is correct — it legitimately can't classify an error with no message. The ELRI harness passes the full task object but the signal dispatch object in ADL has no error_message populated.

### ELRI v5 idempotency key design (confirmed correct)
- **Source dispatch** key: `sha256('dispatch/source/elri:' + dispatch_id)` — does NOT collide with CRC retry space
- **CRC retry key** (from shl-crc.mjs line 268-270): `sha256('dispatch/retry:' + sourceDispatch.id + ':' + taskId)` — different hash space, no collision possible

### What's needed for positive-path ELRI
ADL signal-reader needs to transfer `task.error_message` into `dispatch.error_message` (or `signal.dispatch.error_message`) when emitting TASK_FAILED signals, so that CRC G-S2 can correctly classify the error. Alternatively, the ELRI harness could directly populate `dispatch.error_message` from `task.error_message` when constructing the synthetic signal.
