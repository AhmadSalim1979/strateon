## Priority 1 — WhatsApp Gateway Investigation

**Status:** ⚠️ ROOT CAUSE CONFIRMED — Session invalidation, requires re-authentication

### What I Found (from live gateway logs at `/tmp/openclaw/openclaw-2026-04-29.log`)

**Symptom pattern confirmed:**
- Status `499` = watchdog forcing reconnect because the connection is dying
- The 499 is NOT coming from WhatsApp servers — it's Baileys detecting the connection died and forcing a reconnect
- Connection cycle: establish → survive ~30 seconds → watchdog kills it → repeat

**Root cause — Session Invalidation:**
```
lastInboundAt: 2026-04-29T01:27:14.179Z  (03:27:14 UTC+2)
The session received its last message at 03:27 UTC+2.
After 03:27, the WhatsApp WebSocket started dying every ~30 seconds.
```
- At 03:50 UTC+2 (not 04:00 as originally stated), the connection started dying
- The `authAgeMs` in the logs cycles from ~60s back to ~30s every reconnect — this means new auth is created but immediately invalidated
- WhatsApp is rejecting the session credentials almost immediately after they're created
- "restored corrupted WhatsApp creds.json from backup" = credentials are being corrupted/overwritten by failed reconnect attempts

**The real cause:**
The WhatsApp Web session has been invalidated — the phone number's WhatsApp Web/Desktop session was either:
1. Force-logged out by WhatsApp (due to suspicious activity or session age)
2. Logged in from another device, invalidating this session
3. A network-level issue at the VPS preventing WebSocket handshake completion

The fact that `authAgeMs` keeps resetting to ~30s means a NEW auth session is being created but WhatsApp is immediately closing the WebSocket. This is characteristic of the WhatsApp session being in a "zombie" state — the server acknowledges the auth handshake but immediately drops the connection.

**Evidence from logs:**
- `minutesSinceLastMessage` steadily climbs: 36 → 37 → 38 → 39... (no new messages because the session is dead)
- Every ~30 seconds, a new `connectionId` appears — new connection attempt
- Every new connection has `messagesHandled: 0, lastInboundAt: null` at first, then within one heartbeat (30s) the watchdog fires with `minutesSinceLastMessage: 30+` — meaning no data ever flows
- This confirms: the connection is established but WhatsApp immediately closes it
