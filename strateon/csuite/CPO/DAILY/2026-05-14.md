## Critical Findings This Session

### ⚠️ qiyadon.com/submit-signature — 403 Regression

**What happened:**
The Pages function at `functions/submit-signature.js` fetches directly from `http://5.9.81.5:3001/submit-signature`. Cloudflare Pages security policy blocks outbound fetches to direct origin IP+port, causing HTTP 403.

**Impact:** Frontend has been updated to use `api.qiyadon.com/submit-signature` (Worker route) — real users unaffected. BUT:
- qiyadon.com/submit-signature returns 403 (dead end)
- Any direct caller (webhooks, integrations) hitting qiyadon.com/submit-signature will fail
- This is a regression from the intended design

**Recommended fix:** Update `functions/submit-signature.js` to fetch from `https://api.qiyadon.com/submit-signature` instead of `http://5.9.81.5:3001`. This routes through the Cloudflare Worker which can reach the origin.

**Action needed:** CTO or coder sidecar to make the one-line change.

### ⚠️ strateon-followup-engine — 369 Restarts

**What happened:** Process exits cleanly after each run, PM2 re-spawns on cron. Not a functional failure (it runs successfully every hour), but process management is noisy and wasteful.

**Impact:** Low — engine runs correctly on schedule. But 369 restarts suggests a restart loop that should be diagnosed.

**Action needed:** Investigate why PM2 keeps restarting the process after clean exits. Likely cron schedule misconfiguration or exit behavior.
