## RECITALS

**WHEREAS**, in performing those services, the Data Processor may process personal data on behalf of the Data Controller;

- Regulation (EU) 2016/679 (the "GDPR")
- The UK GDPR (as retained in UK law following Brexit)
- Any other applicable data protection legislation

**NOW, THEREFORE**, the Parties agree as follows:

## 1. DEFINITIONS

### 1.1 Defined Terms
In this DPA, the following terms shall have the meanings set forth below:

| Term | Definition |
|------|------------|
| **Personal Data** | Any information relating to an identified or identifiable natural person ("Data Subject"), as defined under applicable data protection law |
| **Processing** | Any operation or set of operations performed on Personal Data, whether by automated or manual means |
| **Data Controller** | The entity that determines the purposes and means of Processing Personal Data |
| **Data Processor** | The entity that Processes Personal Data on behalf of the Data Controller |
| **Special Category Data** | Personal data revealing racial or ethnic origin, political opinions, religious beliefs, trade union membership, genetic or biometric data, health data, sexual orientation |
| **Sub-processor** | Any third party engaged by the Data Processor to process Personal Data under this DPA |
| **Breach** | A breach of security leading to the accidental or unlawful destruction, loss, alteration, unauthorized disclosure of, or access to Personal Data |
| **Applicable Data Protection Law** | The GDPR, UK GDPR, and any national laws implementing or supplementing them |

### 1.2 Interpretation
Unless otherwise defined in this DPA, terms have the meaning given in Applicable Data Protection Law.

---

## 2. ROLES AND STATUS

### 2.1 Roles
The Data Controller is responsible for determining:
- The categories of Personal Data to be processed
- The purposes of processing
- The legal basis for processing
- Which Data Subjects are affected

The Data Processor shall process Personal Data only on documented instructions from the Data Controller, including with regard to transfers of Personal Data to a third country or international organization, unless required to do so by Applicable Data Protection Law.

### 2.2 Prohibition on Sensitive Data Without Consent
The Data Controller shall not submit Special Category Data to Strateon for processing without prior written disclosure and explicit agreement. Processing of Special Category Data under this DPA requires a separate addendum.

---

## 3. PROCESSING OBLIGATIONS

### 3.1 Instructions
The Data Processor shall process Personal Data only on the documented instructions of the Data Controller as set out in this DPA and the CSA. The Data Processor shall immediately inform the Data Controller if, in its opinion, any instruction infringes Applicable Data Protection Law.

### 3.2 Purpose Limitation
Personal Data shall be processed solely for the purposes of performing the Services as defined in the CSA. Processing for any other purpose is strictly prohibited.

### 3.3 Data Minimization
The Data Processor shall ensure that Personal Data processed is: (a) adequate, sufficient, and not excessive in relation to the purposes for which it is processed; (b) limited to what is necessary for those purposes.

### 3.4 Accuracy
The Data Processor shall not be responsible for verifying the accuracy of Personal Data provided by the Data Controller. The Data Controller is responsible for ensuring data is accurate and up to date.

### 3.5 Storage Limitation
Personal Data shall not be stored longer than necessary for the purposes of the Services. Upon termination of the CSA or upon the Data Controller's written request, the Data Processor shall delete or return all Personal Data in accordance with Clause 9.

### 3.6 Security
The Data Processor shall implement appropriate technical and organizational measures to ensure a level of security appropriate to the risk, including:
- Pseudonymization and encryption of Personal Data
- Ability to ensure confidentiality, integrity, availability, and resilience of processing systems
- Ability to restore availability and access to Personal Data in a timely manner
- Regular testing and evaluation of security measures

**Minimum measures implemented by Strateon:**
- Role-based access controls
- Encrypted data storage and transmission (TLS/AES)
- Access logging and monitoring
- AI execution environments isolated per client
- Regular security reviews

### 3.7 Sub-processors
The Data Controller authorizes the Data Processor to engage sub-processors for specific processing activities. Strateon maintains a list of approved sub-processors. The Data Processor shall:
- Enter into a written agreement with each sub-processor imposing data protection obligations no less protective than this DPA
- Remain fully liable to the Data Controller for the performance of any sub-processor's obligations

The Data Controller may object to the use of a specific sub-processor by providing written notice within [10] business days, in which case the Parties will work in good faith to find an alternative.

### 3.8 Data Subject Rights
The Data Processor shall, taking into account the nature of the processing, assist the Data Controller in fulfilling its obligations to respond to Data Subject requests exercising their rights under Applicable Data Protection Law, including:
- Right of access
- Right to rectification
- Right to erasure ("right to be forgotten")
- Right to restriction of processing
- Right to data portability
- Right to object

The Data Processor shall notify the Data Controller without undue delay (and in any event within [48] hours) of receiving any Data Subject request directly.

## 4. PERSONNEL

### 4.1 Authorization
Personnel authorized to process Personal Data shall be subject to binding confidentiality obligations.

### 4.2 Training
Strateon shall ensure personnel handling Personal Data receive appropriate data protection training.

---

## 5. BREACH NOTIFICATION

### 5.1 Notification
The Data Processor shall notify the Data Controller without undue delay (and in any event within [48] hours) of becoming aware of a Breach affecting Personal Data.

### 5.2 Content of Notification
The notification shall at minimum:
- Describe the nature of the Breach
- Categories and approximate number of Data Subjects affected
- Categories and approximate number of Personal Data records affected
- Name and contact details of the data protection contact
- Likely consequences of the Breach
- Measures taken or proposed to address the Breach

### 5.3 Documentation
The Data Processor shall document all Breaches, including those not affecting Personal Data, and make such documentation available to the Data Controller upon request.

---

## 6. DATA PROTECTION IMPACT ASSESSMENT AND PRIOR CONSULTATION

### 6.1 Assistance
The Data Processor shall assist the Data Controller in conducting any required Data Protection Impact Assessment (DPIA) and prior consultation with the relevant supervisory authority, where applicable.

### 6.3 Responsibility
The Data Controller is responsible for determining whether a DPIA is required.

---

## 7. TRANSFERS OF PERSONAL DATA

### 7.1 Transfers Within the EEA/UK
Personal Data shall not be transferred outside the European Economic Area (EEA) or the UK without the prior written consent of the Data Controller and without ensuring adequate safeguards.

### 7.2 Transfers to Third Countries
If the Data Processor transfers Personal Data to a third country (outside the EEA/UK), it shall ensure that appropriate safeguards are in place, such as:
- Standard Contractual Clauses (SCCs) approved by the European Commission or ICO
- Binding Corporate Rules (BCRs)
- Or another valid transfer mechanism under Applicable Data Protection Law

### 7.3 Post-Brexity
For UK-based Data Controllers, transfers to the EEA are governed by the UK International Data Transfer Agreement (IDTA) or UK Addendum to the EU SCCs.

---

## 8. AUDIT RIGHTS

### 8.1 Right to Audit
The Data Controller may, upon reasonable prior written notice (minimum [10] business days), audit the Data Processor's data processing facilities, records, and relevant documentation to verify compliance with this DPA.

### 8.2 Alternative Verification
Alternatively, the Data Controller may request a summary report or certification from the Data Processor demonstrating implementation of required security measures, in lieu of a full audit.

### 8.3 Audit Costs
The Data Controller shall bear its own costs for any audit. If an audit reveals material non-compliance, the Data Processor shall bear the reasonable costs of the audit.

---

## 9. TERMINATION AND DATA RETURN/DELETION

### 9.1 On Termination
Upon termination of the CSA or this DPA, the Data Processor shall, at the Data Controller's election:
- **(a) Return all Personal Data**: Delivered in a commonly used, machine-readable format, within [30] days of termination; OR
- **(b) Delete all Personal Data**: Permanently destroyed, with written certification provided to the Data Controller within [30] days of termination

### 9.2 Retention Exception
The Data Processor may retain Personal Data if required by applicable law, provided it is kept confidential and processed only to the extent required by law. The Data Processor shall notify the Data Controller of the legal requirement.

---

## 10. LIABILITY

### 10.1 Processor Liability
The Data Processor's liability for claims arising from a Breach or non-compliant processing shall be governed by the liability provisions in the CSA.

### 10.2 Indemnification
The Data Processor shall indemnify the Data Controller for any fines, losses, or claims arising from the Data Processor's breach of its obligations under this DPA or Applicable Data Protection Law.

---

## 11. GOVERNING LAW

### 11.1
This DPA shall be governed by the same law governing the CSA.

## ANNEX II — TECHNICAL AND ORGANIZATIONAL SECURITY MEASURES

Strateon implements the following minimum technical and organizational measures:

**Access Control:**
- Role-based access control (RBAC)
- Multi-factor authentication for all systems handling Personal Data
- Unique user IDs; no shared credentials
- Access logging and review

**Data Security:**
- AES-256 encryption at rest
- TLS 1.2+ encryption in transit
- Data partitioned per client (no shared databases across clients)
- Automated vulnerability scanning

**AI Execution Isolation:**
- Per-client AI execution environments
- Client data not used to train models shared across clients (unless explicitly agreed)
- Prompt inputs and outputs reviewed by human personnel before external delivery

**Physical Security:**
- Data stored in ISO 27001-certified cloud infrastructure
- Physical access controls at data centers (SOC 2 Type II certified providers)

**Incident Response:**
- Documented breach response procedure
- 48-hour notification commitment to Data Controller
- Annual security training for all personnel
